# Воркфлоу n8n

Два воркфлоу по два узла. Импорт: n8n → Workflows → Import from File.

| Файл                    | Что делает                                    | Расписание      |
| ----------------------- | --------------------------------------------- | --------------- |
| `01-sync-reviews.json`  | запускает выгрузку отзывов и черновиков ИИ    | раз в час, :07  |
| `02-flush-answers.json` | досылает очередь ответов на маркетплейсы      | раз в 10 минут  |

Вся работа происходит внутри панели: она сама ходит в Wildberries, Ozon и
OpenAI своими токенами. n8n только дёргает две ручки по расписанию, поэтому
на общем инстансе эти воркфлоу ни с чем не пересекаются.

## Что заменить после импорта

1. **Адрес панели.** В обоих файлах найдите `https://ПАНЕЛЬ.example.com` и
   подставьте свой домен.
2. **Credential.** Плейсхолдер `REPLACE_PANEL_CREDENTIAL_ID` n8n подсветит
   красным. Нужна одна запись типа **Header Auth**: Name `x-api-key`,
   Value - `N8N_API_KEY` панели.

После этого включите оба воркфлоу тумблером Active.

## Зачем второй воркфлоу

Ответ оператора уходит на маркетплейс сразу при нажатии «Поставить», без
участия n8n. `02-flush-answers` подбирает то, что осталось: автоответы и
отзывы, где первая попытка не прошла. Если его не включать, автоответ будет
работать только в момент часовой выгрузки.

## Что вернёт панель

`/api/jobs/sync` отвечает `{ok, results:[{marketplace, fetched, created, drafted, queued, error}]}`,
`/api/jobs/flush` - `{ok, attempted, sent, failed, errors}`. Ошибка площадки
приходит в теле с кодом 200, а не красным узлом, чтобы в истории выполнений
было видно, что именно сломалось. Подробности: [../docs/api.md](../docs/api.md).
